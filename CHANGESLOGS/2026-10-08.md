# 2026-10-08

## New Features
- **The v1.1.0 roadmap, delivered.** The four "Next" items (automatic layout,
  arrow-to-shape binding, zoom-to-fit, align/distribute) and most of "After
  that" (ER diagrams, Mermaid/DBML import, SVG export, richer text) are in,
  together with the MCP surface an agent needs to use them.
  - **Automatic layout.** `flowcraft_diagram` takes `nodes`, `edges`, optional
    `frames`, `direction` (`TB`/`LR`/`BT`/`RL`) and `connectors`
    (`straight`/`elbow`), and returns a map from the caller's node ids to
    element ids. Layering, crossing reduction and spacing are done by the app;
    edges carry no labels.
  - **Arrow-to-shape binding.** Arrows drawn or dragged onto a rectangle,
    ellipse, diamond, triangle or sticky note bind to it and re-anchor on its
    outline whenever it moves, resizes or rotates. Cmd/Ctrl while drawing or
    dropping an endpoint leaves it unattached; MCP uses `fromId`/`toId`
    (`""` detaches). Straight arrows only re-anchor; there is no obstacle
    routing.
  - **Zoom to fit and auto-reframe.** Shift+1 and Edit › Align & view › Zoom to fit; after an
    agent draws, the view fits what was drawn if any of it is off-screen.
  - **Align and distribute.** Edit menu (Align & view submenu) and keyboard: Cmd/Ctrl+Shift+arrows,
    Alt+H / Alt+V (centre), Alt+Shift+H / Alt+Shift+V (distribute, three or
    more).
  - **Frames (F), elbow arrows, an icon library (I) of 24 glyphs, images and ER
    entities** as new element types, each with tool/panel UI and an MCP
    vocabulary entry. Entities have PK/FK rows, arrowheads gained crow's-foot
    cardinalities, and an edge can attach to a specific row.
  - **Images** through Export › Insert image from file… (Cmd/Ctrl+Shift+I) and
    MCP `image` elements (`path` or `dataUrl`), 4 MiB each and 16 MiB per
    scene. Not through paste or drag-and-drop.
  - **Text import.** The paste dialog and `flowcraft_import` read Mermaid
    flowcharts and `erDiagram`, DBML, Excalidraw (import only) and FlowCraft
    JSON, detected from the text. Mermaid `subgraph` becomes a frame.
  - **SVG export** (Export menu and `flowcraft_export`), keeping the
    hand-drawn strokes.
  - **Richer text.** Sans/Mono, bold, and left/centre/right alignment for free
    text.
  - **Link a board to a repo file.** Every save mirrors the scene to a
    `.flowcraft`/`.json` file; a newer linked file wins on load.
  - **MCP surface, from six tools to thirteen.** Added `flowcraft_diagram`,
    `flowcraft_import`, `flowcraft_screenshot`, `flowcraft_export`,
    `flowcraft_guide`, `flowcraft_checkpoint` and `flowcraft_project`
    (list/current/open/create/rename/link/unlink). `flowcraft_read` filters
    by `ids`/`types`/`frame`/`region` and paginates; `flowcraft_draw` replies
    with the new ids. Checkpoints are taken automatically before every
    mutating tool. Agent drawings animate in, with a switch on the System card.

## Design notes — why it is shaped this way
- **Binding is reconciled in one place: `_bumpPaint`.** Every element mutation
  — add, update, translate, resize, align, MCP edit, undo, redo, load —
  already ends in `_bumpPaint`, and selection-only changes do not. Re-anchoring
  bound arrows as its first line means no code path can move a shape and forget
  its arrows, and it runs after the history push, so an undo entry is the
  pre-state and the post-state includes the re-anchored arrows: one entry,
  intact. The geometry is pure (`ArrowBinding`, no controller or widget
  dependency): the endpoint is where a ray from the shape's centre toward the
  other end leaves the outline, found by bisection over the existing hit-test
  predicates, so it is exact for every shape and rotation-aware without a
  per-shape formula. An end aims at the other end's bound shape centre if it is
  bound, otherwise at the other end's stored point, so the result does not
  depend on order and has no circularity. A binding to a deleted shape is
  cleared and the arrow stays where it is.
- **A frame request lives on the controller; viewport state stays in the
  view.** The camera belongs to the canvas widget, which knows its own size.
  The controller only holds a canvas-space *request* (a rect, an
  `onlyIfHidden` flag and a generation counter) and notifies listeners — never
  `_bumpPaint`, so a camera move cannot trigger autosave. The counter, rather
  than the rect, is what the canvas watches, so "fit, pan, fit again" fires
  twice. Automatic requests are dropped while a drag is in progress. Reveal
  (draw-on animation) uses the same shape of channel, and is view-only: the
  model, undo (one `addAll`) and export never see it.
- **Tolerant load instead of a schema bump.** Every new thing is a new element
  `type` or an optional key with a default, so a v1 file with none of them loads
  as before and the schema version stays 1. `SketchSerializer` reads each
  element on its own, so an older build opening a newer file drops the types it
  does not know into the existing "partial scene" banner instead of failing.
  Arrow bindings were already reserved in the format; this release just turns
  them on.
- **Frames are containment, not a `frameId`.** Membership is computed: whatever
  lies wholly inside the frame's rect belongs to it. There is no field to keep
  in sync, no orphan when an element is dragged out, and the `frame` filter of
  read/screenshot/export falls out of the same function. The cost is that
  "inside" is geometric, so overlap does not count. Moving a frame moves its
  unselected members; resizing it leaves them. Hit-testing only the border and
  label keeps clicks inside a frame reaching its children.
- **Elbow routes are derived, never stored.** An elbow arrow keeps its two
  endpoints and a flag; the bends come from `ElbowRouter.route` (horizontal-
  vertical-horizontal, or the reverse when the vertical distance dominates).
  Moving either end therefore re-routes for free and there is nothing to
  migrate. There is no obstacle avoidance by design.
- **The parsers emit the diagram vocabulary.** Mermaid and DBML do not build
  elements; they produce the same `{nodes, edges, frames, direction}` maps
  `flowcraft_diagram` accepts, so layout, validation, size limits and ER
  cardinalities are one code path (`buildDiagram`) and a text diagram looks
  exactly like one sent as JSON. Only Excalidraw, which already has
  coordinates, returns elements directly (and counts what it dropped). A syntax
  error carries its line number and is raised before anything touches the
  canvas.
- **SVG is produced by path sampling.** Re-deriving shapes as SVG primitives
  would have lost the wobble. Instead `SvgExporter` asks the render cache for
  the very paths the painter draws and samples each contour every 2 px into a
  polyline, so the file matches the canvas and the PNG. Text is emitted as
  `<text>` naming Inter and JetBrains Mono rather than embedding them, and
  icons are rasterised.
- **Checkpoints are in memory and keyed by project.** A ring of 20, captured
  by the tool dispatcher itself (a `mutates` flag on each tool) before any
  mutating call, skipping a capture when nothing has changed since the last
  one. Restore is itself history-tracked, so Ctrl+Z undoes it, and a checkpoint
  refuses to restore into a different project, since it would put one
  project's elements on another's canvas. Persisting them would mean a second
  store to keep consistent with the projects; that is on the roadmap.
- **The image policy is plugin-free.** Flutter's clipboard is text-only and
  there is no desktop drop API, so paste and drag-drop would need a plugin —
  and zero plugins is load-bearing here. Images come from a typed path or a
  data URL, through one resolver (`ImageSource`) shared by the dialog and the
  MCP tool, so the refusal a user sees is the one an agent gets. Size caps are
  enforced at parse time, and the render cache decodes each image once.
- **Linking adopts instead of overwriting.** Pointing a board at a path that
  already holds a FlowCraft scene (a cloned repo's `docs/arch.flowcraft`)
  replaces the board with the file and never writes to it; a missing path gets
  the current scene; anything else is refused. The reverse would let one
  mis-click overwrite committed work. On load, a linked file whose mtime is more
  than 2 s past the project's `updatedAt` wins, the slack absorbing the gap
  between a save stamping the project and its own mirror landing.
- **MCP became asynchronous.** Handlers return `FutureOr`, which a screenshot
  (rasterising) and image resolution need. Tools reach the controller, the
  checkpoint ring and a small `McpProjectsHost` of closures through one context
  object, so the server never imports the Riverpod layer.

## Glass Canvas redesign

### New / Changed
- **Islands.** The chrome is a set of floating glass islands: top-left logo, project name and
  Projects popover; top-centre a tool pill (14 tools); top-right the Agents chip and popover, the
  Edit menu and an accent Export button; left the Inspector; bottom-right Undo, Redo, Grid, Theme.
- **One control per place.** Undo/Redo only bottom-right (shortcuts unchanged), Delete only in the
  Edit menu, Clear canvas in the Edit menu's Canvas group (with an Undo snackbar), no History group.
- **Agents chip and popover** replace the MCP/System card: MCP Server switch, Animate agent drawing
  switch, endpoint / Copy connect / Setup only while running, reason + Retry on failure. The Connect
  dialog is four tabs.
- **Projects popover** replaces the drawer; row "…" menu: Rename, Link to file… / Unlink file, Delete.
- **Inspector** replaces the style popovers and the properties panel: style for one or many
  elements, or for the next shape while a drawing tool is active; arrow, position, kind and font
  sections; Edit JSON.
- **Fonts and icons.** UI font Geist + Geist Mono (OFL, `assets/fonts/`, licences alongside); canvas
  fonts stay Inter / JetBrains Mono. Chrome icons are Lucide (ISC,
  `assets/icons/Lucide-LICENSE.txt`) via `FcIcons` / `FcIconGlyph`. New dependency: `path_parsing`.
- Light theme hand-tuned and still the default.

### Design notes — why it is shaped this way
- **One control per place.** Duplicated Undo/Clear/Delete across toolbar, menu and panel were each a
  place for state to drift; the Edit menu is now the single home for commands and the island for
  history.
- **Tokens as ThemeExtension + ColorScheme.** `FcTokens` (`context.fc`) carries the glass-specific
  values; `ColorScheme` still feeds stock Material widgets, so both stay in step per theme.
- **One glass card.** Islands, menus, popovers and dialogs share the same blurred glass surface
  (sigma 24, CSS `blur(24px)`); `blurSigma` 0 turns blur off for slow Windows/Linux GPUs.
- **Icons rendered from the mockup's SVG data, not an icon font**, so the 1.75 stroke matches the
  design exactly; `path_parsing` (pure Dart, not a plugin) is the one approved dependency, keeping
  zero Flutter plugins intact.
- **Static Geist TTFs** (5 files, ~680 KB, unsubsetted) because Flutter's `fontWeight` does not
  drive a variable font's `wght` axis.
- **The Inspector keeps multi-select and pre-draw styling**, so redesigning did not remove
  v1.1.0 capabilities.
