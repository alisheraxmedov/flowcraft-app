# 2026-08-22

## Architecture
- **The MCP server moved inside the app.** `FlowcraftControlServer` now serves
  `/mcp` — a spec-compliant MCP endpoint over the **Streamable HTTP**
  transport — straight into the live `SketchController`, hand-rolled on
  `dart:io` + `dart:convert` with no new dependency. Users register the
  running app with
  `claude mcp add --transport http flowcraft http://127.0.0.1:5199/mcp --header "X-Flowcraft-Token: <token>"`.
  The separate precompiled `mcp_server` binary is no longer built or published
  by CI; the app installer is now the only artifact an end user needs.
  `mcp_server/` survives as an optional legacy stdio bridge for MCP clients
  that can't speak HTTP.
- `flowcraft_launch` was dropped from the tool list — it only existed because
  the out-of-process bridge could find the app closed, which is impossible now
  that the server *is* the app. `flowcraft_status`, `flowcraft_draw` and
  `flowcraft_clear` keep their names and schemas.
- New persistence layer: `ProjectRepository` (`~/.flowcraft/projects/`, one
  atomically-written JSON file per whiteboard), `ProjectsViewModel`, and
  `ProjectAutosave` (debounced write-behind, flushed on project switch and on
  app exit). `index.json` is a rebuildable cache, never the source of truth.
- New `CanvasExporter` renders the whole scene to PNG off-screen via
  `PictureRecorder` + the existing `SketchPainter`, independent of the
  viewport. Both it and the repository use `_io`/`_stub` conditional-import
  pairs so `flutter build web` keeps working with zero Flutter plugins.

## New Features
- **Saved projects, chat-history style.** A sidebar (menu button in the top
  bar) lists every whiteboard with its element count and last-updated time:
  new, rename, delete, switch. The open project's name sits in the top bar
  and is click-to-rename. Everything autosaves as you draw; the splash screen
  now waits for the restore so the canvas is never briefly empty.
- **Export menu** replacing the old JSON-to-clipboard button: PNG (whole
  scene, 2×, padded), JSON (versioned `SketchSerializer` format), or
  clipboard. Files land timestamped in `~/Documents/FlowCraft/` with a
  **Reveal** action in the confirmation. No native save dialog on purpose —
  a file-picker plugin would break the zero-plugin property the macOS build
  depends on.
- The MCP card now shows the live endpoint, a **Copy connect** button, and a
  **Setup** dialog with ready-made config for Claude Code, Codex CLI and
  Gemini CLI.

## Bug Fixes
- **Picking a fill colour did nothing.** Two stacked causes: the toolbar only
  wrote `currentStyle` (the default for *new* elements) and never touched the
  selection, and `fillStyle` defaults to `none`, which the painter skips — so
  even a correctly-applied colour stayed invisible. All six style controls now
  apply to the selection in a single undo entry, and choosing a fill colour
  promotes `fillStyle` to `solid`.
- **Clicking existing text spawned a second text box.** `SketchText.bounds`
  guessed its width as `text.length * fontSize * 0.55` while the painter laid
  out real glyphs — `"Hello"` at 16pt measures 80×16, the guess claimed 44×20.
  Clicks on the uncovered half missed the hit test and fell through to
  "create a new text here". Bounds are now measured with a cached
  `TextPainter` shared with the painter, and the text hit test takes a
  tolerance.
- The inline editor's glyphs jumped `(5, 3)px` when editing began and back on
  commit, and ignored the element's `fontFamily`; sticky-note labels were off
  by the painter's 8px inset. All now align with what is painted.
- **Click-to-select pushed an undo entry**, so `canUndo` went true and the
  first Ctrl+Z visibly did nothing. Drag sessions now *arm* a snapshot that
  only the first real mutation commits.
- Hit tolerance was passed to canvas-space tests without dividing by zoom, so
  the grab radius was 4× too generous at 4× zoom and 4× too mean at 0.25×.
  Now a constant ~8 screen pixels at any zoom.
- The toolbar always rendered `currentStyle`, so selecting a red 6px shape
  still showed black 2px. It now reflects the selection, with a neutral
  "mixed" indicator for multi-selections that disagree.
- **The MCP switch could show a green "Online" over a dead endpoint.** If the
  port was taken the switch still settled ON with no endpoint and no
  explanation. State is now `off / starting / running / failed`; a failed bind
  shows the reason and a Retry, and withholds the connect command.
- Disposing the control server bypassed its transition queue, so quitting mid
  start-up leaked the bound socket and held the port.
- Undo straight after a project switch would have pulled the previous
  project's elements onto the new canvas (and autosaved them into the wrong
  file) — opening a project now uses `SketchController.loadScene`, which
  discards history.

## Code Quality
- `flowcraft_control_server.dart` reduced to a thin HTTP router; the MCP
  protocol and the tools live in `mcp_http_handler.dart` and `mcp_tools.dart`.
  The MCP card moved out of `whiteboard_view.dart` into its own widget.
- The fill-colour ⇄ fill-style coupling lives in one place
  (`SketchStyle.withFillColor` / `withFillStyle`), used by both the toolbar
  and the properties panel, which previously disagreed.
- Tests no longer bind the fixed port 5199. `mcpServerPortProvider` lets every
  test take an OS-assigned port, killing a real source of "red on CI, green on
  re-run" — a rule now documented in `CLAUDE.md`.
- 264 tests passing, `flutter analyze` clean, `flutter build web` verified.

# 2026-08-22 (second batch) — editing basics, hardening, and going public

## New Features
- **Keyboard shortcuts, app-wide.** One `Shortcuts`/`Actions` layer replaces the
  five keys the canvas widget used to handle in a method scoped to its own
  focus node — which also meant every shortcut died the moment you touched a
  toolbar popover or a text field. Tool keys are Excalidraw's exactly
  (`V H R O D L A P T E`, plus `G` triangle and `N` sticky) so muscle memory
  carries over. Adds copy/cut/paste/duplicate/select-all, z-order, group and
  ungroup, 1px and 10px nudge, and `?` for a reference sheet. Bindings,
  reference sheet and the new top-bar **Edit** menu are all generated from one
  table, so they cannot drift apart.
- **Copy / paste / duplicate** through the system clipboard in the versioned
  scene format, so it works between two FlowCraft windows. Pasted and
  duplicated elements get fresh ids, and a duplicated group becomes a new
  independent group.
- **Grouping**, z-order, and group-aware selection — clicking any member
  selects the whole group.
- **Draggable line and arrow endpoints.** Previously an arrow drawn slightly
  wrong could only be deleted and redrawn, or edited through the JSON dialog.
- **Eight resize handles** instead of one bottom-right handle, with `Shift` to
  preserve the aspect ratio. A box can finally be grown up and to the left.
- **Snapping** to the grid and to other elements' edges and centres, with a
  guide line showing why it snapped, and `Alt` to suppress it.
- **Scene import** — from a list of your own exports, from a typed path, or
  from pasted JSON, added to the canvas or replacing it. The README described
  the exported JSON as re-importable; now it is.
- **Bundled typefaces.** Inter and JetBrains Mono ship as assets instead of
  being fetched by `google_fonts` from Google's CDN on first run. The app now
  makes no outbound network request at all, which is what a local-first tool
  should have been doing from the start.

## Bug Fixes
- **A single unreadable element made a whole project unopenable.** Scene
  loading is now per-element tolerant, and — critically — autosave *stops*
  while a scene is partial, with a banner explaining why, so the reduced scene
  can never overwrite the original file. Previously the 800ms debounce would
  have made the loss permanent within a second of opening the file.
- **Autosave fired on selection changes.** `_schedule` was wired to every
  `ChangeNotifier` notification, so merely clicking an element wrote an
  unmodified scene to disk, bumped `updatedAt` and re-sorted the project
  sidebar under the user. It now tracks `paintGen`, which only visual
  mutations bump.
- **A cancelled drag wedged the controller.** `_onPointerCancel` never ended
  the drag session, so the *next* drag recorded no undo entry at all and one
  Ctrl+Z jumped back two drags. Reachable for real on desktop when the window
  loses focus mid-drag.
- Marquee selection treated a shared edge as disjoint, so a band drawn flush
  along an axis-aligned connector selected nothing; and it used bounding boxes
  for lines, so a band clipping only the empty corner of a diagonal arrow's
  bbox selected it. Linear elements now test their actual segment.
- Resize handles were drawn at `bounds + 4px` but hit-tested at bare `bounds`
  — a 4px mismatch between what you saw and what you could grab.

## Security
Audited before making the repository public: 54 commits across every ref,
1,151 blob/path pairs, 21 credential families, validated against a positive
control. **No secret was ever committed** and nothing needed rotating. Six real
defects in the network- and filesystem-facing code were found and fixed:

- **Path traversal (CWE-22)** — a project's id was trusted from the *contents*
  of its scene file, not its filename, so a crafted file dropped into
  `~/.flowcraft/projects/` could read or delete arbitrary `.json` paths. Ids
  are now validated at one door, and the filename decides identity.
- **World-readable auth token (CWE-732)** — `~/.flowcraft/control.token` was
  written `0644`, contradicting its own doc comment. Real on Debian/Ubuntu,
  where `adduser` leaves home directories `0755`.
- **Unbounded request bodies and element counts (CWE-770)** — now capped, with
  the MCP tool returning a correctable error telling the model to split the
  diagram.
- **Non-finite geometry (CWE-1284)** — JSON `1e999` decodes to `Infinity` and
  reached the renderer.
- Non-constant-time token comparison (CWE-208) and raw exception text returned
  to clients (CWE-209).

Also: `LICENSE` contained `TODO: Add your license here.` while the README
claimed MIT — a public repo with no license text is all-rights-reserved. The
MIT text is now in place. The Windows installer pointed at the legacy
repository URL.

## Code Quality
- `groupId` on the element base and reserved `startBinding`/`endBinding` fields
  on `SketchArrow` round-trip through JSON while unused, so grouping and
  arrow-to-shape binding land later **without** a schema bump that would
  strand every scene a v1 user saved.
- `SketchGeometry.handlePosition` is the single source both the painter and the
  hit test read, which is what closed the 4px handle mismatch.
- 467 tests passing (264 → 467), `flutter analyze` clean, `flutter build web`
  and `flutter build macos` verified, and the MCP endpoint checked end-to-end
  against the running app with a real HTTP client.

# 2026-08-22 (third batch) — sticky notes as chat bubbles

## New Features
- **Sticky notes are chat bubbles that collapse to a badge.** A note is now
  drawn as a messenger-style bubble — a saturated amber body with a curled
  tail at the bottom-left — and collapses to a 40px rounded badge carrying a
  small outline of that same bubble. **One rule:** a note is open while the
  pointer is on it, and a click anywhere else on the board closes it, every
  time; clicking the badge opens it again. Editing is orthogonal: a click
  away that also ends an edit commits the text and the note is already
  closed by the time it does. The point is that a board can carry many
  notes without them swamping the diagram: they sit collapsed until wanted.
  - The first cut hung collapse off the text commit, which closed a note
    exactly once — reopen it from the badge, click away, and with no edit to
    commit nothing fired. Collapse now runs on pointer-**down** in the
    gesture handler for every tool but the hand (a pan is navigation, not a
    click on the board), keyed on what the press resolved to: the note
    itself or one of its resize handles keeps it open; empty canvas,
    another element, another note, or the start of a marquee closes it.
    Clicks on app chrome never reach the canvas, so a note stays open
    through them — the user is doing something else and the note can wait.
  - **Open-or-closed is not undoable.** It is view state the way selection
    is: cheap to redo by hand, and a side-effect of clicks whose purpose was
    something else, so an undo entry per toggle would make Ctrl+Z reopen a
    note instead of undoing the thing the user actually did. Unlike
    selection it *is* persisted, because a board should come back the way it
    was left.
  - The tail is at the **bottom-left**: the text is left-aligned and reads
    from there, and a left tail is the "received message" side in every
    messenger — the neutral, someone-left-a-note reading.
  - The bubble is **drawn clean, not rough**, whatever the element's
    roughness. Through `RoughGenerator` it was a frayed yellow blob: the
    generator draws square corners over a rounded fill, and at badge size
    the wobble turned the mark into a scribble. A chat bubble is a clean
    silhouette in every messenger; the hand-drawn register lives in the
    text and in everything the note annotates. The outline is the *same
    path* as the fill, so it hugs it exactly.
  - **Escape** keeps its meaning for the text — nothing is committed — and
    the next click away closes the note like any other; no state is immune.
- **Notes grow to fit their text, and default smaller.** There was never a
  default: the sticky tool made a note the size of the drag rect, and a
  plain click produced a 0×0 rect the commit path then discarded, so
  clicking with the sticky tool did nothing. A press now drops a 180×72
  note; a smaller drag is floored to it; and on commit a note grows (never
  shrinks) until its text fits, the way a bubble takes the height of its
  message — previously a third line ran out through the tail. The label
  drops from 20pt to the 16pt every other element uses, and the composer
  grows while typing so the third line does not scroll out of sight.

## Bug Fixes
- **A sticky's label was invisible.** `SketchSticky.create` set stroke and
  fill from one colour and the painter drew the label in the stroke colour
  — pale yellow on pale yellow, in the canvas and the inline editor alike.
  Glyphs now take `SketchSticky.inkColor`, derived from the paper's
  luminance, which also follows a fill the user picks from the palette.

## Code Quality
- New `StickyBubbleGeometry` is the single source for the bubble's shape:
  `SketchSticky.bounds`, `SketchRenderCache`'s fill and outline, the
  painter's label box, the inline editor's glyph box and the grow-to-fit
  height all read it. Same rule as `SketchGeometry.handlePosition`.
- **`SketchSticky.bounds` is the badge while collapsed**, so selection,
  hit-testing, marquee, viewport culling and PNG export all see the box that
  is actually painted — the defect `SketchText.bounds` shipped.
- `SketchHitTest.isResizable` replaces the two copies the painter and the
  gesture handler each held: one asks whether to *draw* the eight handles,
  the other whether to *grab* them. A collapsed note has none.
- `TextMetrics.layout`/`measure` take a `maxWidth`, so the painter, the
  editor and `fittedToText` wrap a label through one call.
- Opening a collapsed note happens on pointer-**up**, and only when the move
  session never translated anything — the same press is how a note is
  dragged.
- `collapsed` is omitted from `toJson` when false and defaulted on read, so
  a scene with no collapsed notes serialises byte-for-byte as before and
  `SketchSerializer.schemaVersion` stays at 1.
- 558 tests passing (476 → 558), `flutter analyze` clean, `flutter build
  web` verified, and every sticky state rendered to PNG and inspected.
