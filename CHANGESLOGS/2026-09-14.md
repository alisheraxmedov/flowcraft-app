# 2026-09-14

## New Features
- **The MCP surface can now read the canvas back and edit it, not only draw
  onto it.** Until now an agent had two options — `flowcraft_draw` mode
  `"add"` (append) and `"replace"` (wipe and redraw) — so correcting a single
  misplaced box meant either duplicating the whole diagram or clearing the
  board. Three tools close that gap, delivering the "richer MCP surface"
  roadmap item:
  - `flowcraft_read` returns every element on the canvas as JSON, each with
    its `id`, `type`, geometry, text and colours.
  - `flowcraft_update` edits existing elements in place, addressing each by
    `id` and overriding only the fields present in the patch — position,
    size, colour, label — while leaving every other field and every other
    element untouched.
  - `flowcraft_delete` removes specific elements by `id`.
  A typical loop is now draw → read (to learn the ids) → update/delete the one
  or two elements that came out wrong.

## Design notes — why it is shaped this way
- **Read and edit speak the *same words* as draw.** `describeDiagramElement`
  is the deliberate inverse of the draw parser's `_parseOne`: it emits the
  exact field vocabulary `flowcraft_draw` accepts (`type`, `x`/`y`/`width`/
  `height`, `fromX`/`fromY`/`toX`/`toY`, `text`, `fontSize`, `strokeColor`,
  `fillColor`) plus the element's `id`. An agent can therefore take a
  `flowcraft_read` result, change a couple of fields, and feed it straight
  into `flowcraft_update` with no second mental model — and the update schema
  literally shares the draw schema's per-element property map (`_elementProperties`),
  so the two can't drift apart. Colours are emitted as 8-digit `#AARRGGBB` so
  they round-trip through the existing `_color` validator exactly, alpha and
  all, rather than coming back 6-digit and silently resetting opacity.
- **A patch means "change only what I named."** `applyDiagramPatch` returns a
  new element of the *same concrete type* with the patched fields overridden
  and everything else — crucially `id`, `angle`, `groupId`, and any geometry,
  style or text the patch didn't mention — preserved. It reuses the draw
  path's validators (`_number`, `_dimension`, `_fontSize`, `_color`), but with
  the element's *current* value as the fallback, so an omitted field is
  "unchanged" instead of snapping back to a default. An explicit empty `text`
  clears a bounded shape's label.
- **Type changes are refused.** A `type` in a patch that disagrees with the
  target element is an error, not a silent no-op: a rectangle and an arrow
  share no geometry, so quietly discarding the mismatched fields would be
  worse than telling the agent to delete the element and draw the new kind.
- **`SketchText` cannot be emptied, freehand geometry cannot be edited.** A
  text element *is* its text, so an empty `text` on one is refused with a
  message pointing at `flowcraft_delete` — the same reason committing an empty
  text edit in the UI removes the element. Freehand strokes are a raw point
  list the draw/update vocabulary has no field for, so a geometry field in a
  freedraw patch is refused (only a recolour is honoured); `flowcraft_read`
  still lists a freedraw by its bounding box so an agent can at least delete
  it by id.
- **Batch edits are one undo entry.** Two new controller methods,
  `updateAll` and `removeIds`, back the tools. They mirror the existing
  `addAll`/`removeSelected` convention: a single `flowcraft_update` or
  `flowcraft_delete` naming several elements pushes exactly one history entry,
  so a user's Ctrl+Z takes the whole agent edit back in one step rather than
  one press per element — and, like `addAll`, they push no history and bump
  no paint when nothing matched, so a patch that addresses only stale ids
  leaves no empty undo step behind. `removeIds` also drops the deleted ids
  from the selection, so a selection can't outlive the element it pointed at.
- **`flowcraft_update` reports, rather than hides, stale ids.** Ids not on the
  canvas are collected and named back to the agent while the rest of the batch
  applies; a batch where *nothing* matched is a tool error (with `isError`),
  so the model re-reads for current ids instead of believing a silent success.

## Code Quality
- The draw and update schemas share one `const` per-element property map, so
  the field vocabulary is defined once. `_fontSize` is now a thin wrapper over
  a new `_fontSizeOr(map, fallback)` so the patch path can default to the
  element's current size without duplicating the range check.
- Tests: `updateAll`/`removeIds` unit-tested for matched/ignored ids, single
  undo entry and returned counts; `describeDiagramElement`/`applyDiagramPatch`
  covered per element type, including round-trip, empty-text clearing,
  type-mismatch and freedraw-geometry rejection, and reuse of the range/
  finiteness/hex validators; and the three tools driven end-to-end over a real
  loopback `McpHttpHandler` (and through the full control server) — read a
  drawn scene back, update one element by id and assert only it changed,
  delete by id and assert the rest survive.
